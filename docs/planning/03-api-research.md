# Российские площадки и API

Дата проверки: **16 сентября 2026 года**.

## Вывод для MVP

Для MVP следует подключать **только один внешний источник — открытый API
вакансий «Работы России»**, и только в режиме чтения. Это не дополнительный
каталог, а источник основного полезного результата: по должности и региону
сервис получает живую выборку, рассчитывает количество конкурирующих вакансий,
зарплатную медиану/вилку, позицию предложения и список работодателей.

hh.ru, SuperJob, Авито Работа, Работа.ру, Факультетус и Хабр Карьера имеют
документированные API или официально подтверждают наличие API, но доступ к
нужным функциям зависит от регистрации приложения, авторизованного аккаунта,
тарифа, активации или согласования. Их нельзя ставить на критический путь
хакатонного MVP. Они входят в Won't Have. Парсинг сайтов как запасной способ
**не допускается**.

## Метод и границы проверки

- Использовались только официальные сайты, документация, правила и developer
  portals владельцев площадок. Сторонние обзоры не использовались как основание
  выводов.
- «Документация существует» не трактуется как «доступ гарантирован». Отдельно
  проверены публичные вакансии, кабинет работодателя, персональные данные
  резюме и действия с откликами.
- Без ключей были выполнены безопасные read-only проверки. Запрос к
  [открытому API «Работы России»](https://opendata.trudvsem.ru/api/v1/vacancies?limit=1)
  вернул `200` и одну актуальную вакансию. Анонимные запросы к поиску вакансий
  [hh.ru](https://api.hh.ru/vacancies?per_page=1) и
  [SuperJob](https://api.superjob.ru/2.0/vacancies/?count=1) вернули `403`.
  Проверки с пользовательскими аккаунтами, платными тарифами и персональными
  данными не выполнялись.
- PDF прочитан полностью. Он запрещает закрытые библиотеки, частные API и чужой
  код без разрешения на свободное распространение/использование (с. 7), требует
  маркировать модельные данные (с. 7, 18) и прямо называет «Работу России»
  официальным источником для исследования найма (с. 21).
- «Не подтверждено» ниже означает, что соответствующее условие не найдено в
  доступном официальном источнике; это не разрешение и не запрет.

## Почему выбран именно один источник

### «Работа России»: live market source

Интеграция решает основную задачу: по title/query и коду региона получить
наблюдаемое предложение рынка для линейной роли. Нужные публичные поля:

- внешний ID, canonical URL и дата изменения;
- название вакансии и регион;
- наименование работодателя;
- минимальная/максимальная зарплата, валюта и период оплаты;
- при наличии — занятость/график только как объясняющий фильтр.

Приложение не публикует вакансии на «Работе России», не читает кабинет, не
получает резюме и не действует от имени пользователя.

### Live query contract

До реализации `TRUD-002` задача `TRUD-001` должна подтвердить точный endpoint и
параметры актуальной версии API. Контракт приложения требует:

1. server-side GET с title/query и region code;
2. явные connect/read timeout, User-Agent и предел страниц/общего времени;
3. стабильную нормализацию пагинации и source errors;
4. сохранение query, `fetched_at`, общего числа результатов и размера пригодной
   зарплатной выборки;
5. атрибуцию и ссылки на `trudvsem.ru`.

В dashboard нельзя показывать только итоговую медиану без query, даты и размера
выборки: такой результат невозможно проверить или правильно интерпретировать.

### Зарплатная пригодность

MVP сравнивает месячные суммы в RUB. Вакансия входит в распределение, только если
обе границы зарплаты и период позволяют однозначное сравнение. Midpoint
диапазона участвует в медиане и percentile; market range строится по исходным
границам. Одна граница, неизвестный период, другая валюта и отсутствующая
зарплата получают отдельные exclusion reasons.

`total_found` и `salary_sample_size` — разные показатели. При sample меньше
зафиксированного порога UI показывает «недостаточно данных», а не рекомендацию.

### Минимальная модель хранения

Для первичного ответа достаточно агрегированного `MarketSnapshot` и небольшого
набора публичных конкурентных записей: source ID/URL, employer, title, salary,
`source_updated_at`, `fetched_at`. Сырой ответ, email, имя и телефон контактного
лица не хранятся.

Для следующего мониторинга новый snapshot сравнивается с предыдущим. Полный
локальный клон открытого каталога, архив всех вакансий России и постоянная
синхронизация без активных пользовательских мониторингов не нужны.

### Проверяемость жюри

Проверка не требует секрета:

1. выполнить live benchmark для заранее указанной роли/региона;
2. показать query, источник, `fetched_at`, `total_found` и `salary_sample_size`;
3. открыть 2–3 source links и сопоставить работодателя/зарплату;
4. воспроизвести расчёт на сохранённом обезличенном наборе чисел;
5. повторить запрос и доказать новый snapshot без дублирования алерта.

## Резервный сценарий

Живой источник входит в Must Have. При таймауте, `429`, `5xx`, schema drift или
юридическом блокере приложение показывает «Источник временно недоступен» и дату
последнего успешного среза. Отдельный synthetic fixture допустим для тестов и
backup demo только с явной меткой «Демо-данные»; он не закрывает acceptance
живой интеграции. Парсинг HTML и незаметное переключение на другой API
запрещены.

## Доступ пользователей и пилот

Для пилота нужны 3–5 владельцев малого бизнеса или HR, которые реально влияют
на условия линейных вакансий. Они приходят через прямой outreach, локальное
бизнес-сообщество или отраслевого партнёра. Candidate acquisition продукту не
нужен: сервис не является job marketplace. Командное распространение происходит
через выбранный канал MAX после явной привязки бота.

## Совместимость с условиями PDF

PDF запрещает закрытые библиотеки, частные API и чужой код без разрешения на
свободное распространение/использование (с. 7). Он также требует не имитировать
недоступную интеграцию и явно маркировать синтетические данные (с. 7, 18).
Оценка для выбранного решения:

- «Работа России» публикует open-data API, который работает обычными HTTPS GET
  и JSON; закрытый SDK или библиотека не нужны. Это наименее рискованный вариант.
- hh.ru, SuperJob, Авито Работа, Работа.ру, Факультетус и Хабр Карьера требуют
  ключ, аккаунт, OAuth, активацию, тариф или согласование хотя бы для части
  нужного сценария. Сам OAuth не делает публично документированный API
  «частным», но недоступный команде/жюри контракт, партнёрский endpoint или
  закрытая библиотека нарушают воспроизводимость и могут попасть под прямой
  запрет страницы 7. Поэтому их нет в MVP без письменного разрешительного gate.
- Даже документированный API не должен попадать в P0, если его нельзя открыть
  жюри без личного/платного аккаунта или заранее выданного доступа.
- Тестовые данные должны быть синтетическими и явно маркированными; нельзя
  выдавать fixture за результат live benchmark или реальный market snapshot.

Read-only API «Работы России» остаётся рекомендуемым: он опубликован как API
открытых данных, работает обычным HTTPS/JSON без закрытого SDK и указан самим
PDF среди официальных источников (с. 21). Перед сдачей всё равно нужно сохранить
доказательство актуальных условий, атрибуции и лицензионной допустимости.

## Неразрешённые вопросы перед разработкой

1. Зафиксировать поля «Работы России», которые разрешено отображать и хранить;
   проверить актуальные типовые условия открытых данных и атрибуцию.
2. Проверить на нескольких линейных ролях долю вакансий с двумя сопоставимыми
   границами зарплаты и выбрать минимальный размер выборки.
3. Зафиксировать relevance sample текстового поиска и честную формулировку
   ограничений результата.
4. Согласовать срок хранения snapshots/competitor rows и поведение при
   недоступности источника.
5. Проверить лицензии всех добавляемых клиентских библиотек: PDF отдельно
   запрещает закрытые и несвободно распространяемые зависимости (с. 7).
6. Не начинать вторую job-интеграцию: она прямо находится в Won't Have MVP.
